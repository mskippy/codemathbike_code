2.4 Assembly: Going Live Without Git

Your computer doesn't have Git installed, and that's fine. You'll still put your site on GitHub, make real commits, and end up with the same live site at https://your-username.github.io. The difference is that you'll upload your files on github.com instead of pushing them from VS Code. You keep working in VS Code on your H: drive exactly like you have all unit, with Live Preview.

Do these first, on the main 2.4 page: Task 1 — Pre-flight check (including the 20 Questions oversharing audit) and Task 2 — GitHub account. Then come back here for Tasks 3–6.

Find your spot

  • Task 3 — Create your repo and upload your site: you have a GitHub account, but no repo yet.
  • Task 4 — AI code cleanup: your files are uploaded.
  • Task 5 — Go live: your "AI code cleanup" commit is done.
  • Task 6 — Ship an update: your site is live.

How the no-Git path works

  • VS Code on your H: drive is where you edit and test, the same as always.
  • github.com is where you upload. Every time you upload and click Commit changes, that's a commit, and your live site updates.
  • The loop: edit and save in VS Code → upload to GitHub → commit.

Task 3 — Create your repo and upload your site

Uploading your files for the first time counts as your first commit.

Step 1: Make your email private (before you upload anything)

  1. On github.com, click your profile picture (top right) → Settings → Emails (left menu).
  2. Turn on Keep my email addresses private. Every commit you make on the website now uses a private address instead of your school email. There's nothing to copy.

Step 2: Create your repository

  1. On github.com, click the + at the top right → New repository.
  2. Repository name: type exactly 
    your-username.github.io
    using your GitHub username, spelled exactly the way it is on GitHub.
  3. Make sure Public is selected. (Free GitHub sites have to be public.)
  4. Leave everything else as it is, and don't tick "Add a README." Click Create repository.

Step 3: Upload your files

  1. On your new, empty repo page, find the Quick setup box and click the link that says uploading an existing file.
  2. Open File Explorer and go inside your project folder: H:\ICT 9\2_web_development\your-slug. You should see index.html, about.html, work.html, and the css, js, and images folders.
  3. Press Ctrl + A to select everything inside the folder, then drag it all into the browser, onto the upload box.
  4. Wait until every file is listed underneath, including the ones inside css, js, and images.
  5. Scroll down to Commit changes. In the message box, type First version of my studio code.
  6. Leave Commit directly to the main branch selected, and click Commit changes.
Common mistake: drag the stuff inside your folder, not the folder itself. If you drag the whole your-slug folder, GitHub puts everything inside a your-slug folder, and your site shows a 404. index.html should be listed right at the top level of your repo, next to the css, images, and js folders.
🟢 Green: your repo is named your-username.github.io, says Public, and shows index.html, about.html, work.html, css, images, and js at the top level.
🔴 Red: the name is wrong? Go to Settings → change the Repository name → Rename. Everything ended up inside one folder? It's easiest to delete the repo (Settings → scroll to Danger Zone → Delete this repository) and redo Steps 2–3.
Green

Task 4 — AI code review: clean up the scary code

Same job as the VS Code path: get an AI to clean up your code, and you're the one who approves it. On this path you test the changes in Live Preview first, upload them, and then review exactly what changed on GitHub.

Step 1: Clean up one file at a time in VS Code

  1. Copy the AI prompt from Task 4 on the main page into the AI tool of your choice (any of the ones allowed in class).
  2. In VS Code, open index.html, press Ctrl + A then Ctrl + C, and paste it into the AI right after the prompt.
  3. Copy the AI's cleaned-up file, select everything in index.html (Ctrl + A), and paste over it. Save.
  4. Check Live Preview. The page should look and work exactly like before. Click everything, including your JavaScript buttons.
  5. Broken? Press Ctrl + Z to undo the paste, and try again (or paste only the messy part).
  6. Repeat for about.html, work.html, css/style.css, and js/script.js.

Step 2: Upload your cleaned-up files

  1. On github.com, go to your repo's front page (not inside a folder) → Add file → Upload files.
  2. Drag in everything inside your your-slug folder again, the same way as Task 3. Files with the same name replace the old ones, and GitHub ignores anything that didn't change.
  3. Commit message: AI code cleanup → Commit changes.

Step 3: Review every change on GitHub (the important part)

  1. On your repo's front page, click the commits link (the clock icon near the top of your file list).
  2. Click your AI code cleanup commit. GitHub shows every file that changed: red is what the AI removed, and green is what it added.
  3. Read every change. For each one, you should be able to say what it does. Don't understand one? Ask the AI: "Explain this change like I'm new to coding."
  4. Don't want to keep a change? Fix it in VS Code, save, and upload again with a message like Undo AI change to nav.
Watch the AI closely. It makes mistakes too. Red flags to look for in the changes:
  • A new <script src="https://..."> or <link href="https://..."> pointing to another website that you didn't add.
  • A changed id or class name. This silently breaks your JavaScript or CSS.
  • Your own words rewritten, or whole sections gone missing.
  • A file that suddenly got much longer. The AI probably added features you didn't ask for.
This is your AI reflection for this lesson. When you submit, answer the usual questions: what you asked, what it gave you, what you kept or rejected (and why), and one thing you learned from its list of changes.
🟢 Green: your site still works in Live Preview, the "AI code cleanup" commit is in your repo's commit list, and you can explain at least three changes the AI made.
🔴 Red: the commit shows no changes. The AI's versions probably weren't saved in VS Code before you uploaded. Save every file (or turn on File > Auto Save) and upload again.
Green

Task 5 — Turn on GitHub Pages and go live

  1. On your repo page, click Settings (the gear tab along the top) → Pages in the left menu.
  2. Under Build and deployment → Source, choose Deploy from a branch.
  3. Under Branch, choose main and / (root), then click Save.
  4. Wait 1 to 5 minutes. Watch for a green check under Deployments on the right side of your repo's front page (or in the Actions tab). Refresh the Pages settings and your live link appears at the top.

Test it for real

  1. Open https://your-username.github.io. That's your site, live on the internet.
  2. Click every nav link and every button. Check that your avatar shows up.
  3. Open it on your phone too.
  4. Post your live URL to the 2.4 Teams assignment.
🟢 Green: your site loads at https://your-username.github.io on a different device, every page and image works, and the URL is posted in Teams.
🔴 Red: a 404 means GitHub can't find index.html at the top level of your repo (see the Common mistake in Task 3). A broken image that works in Live Preview is almost always a capital letter in the file name. See the renaming note in Task 6.
Green

Task 6 — Ship an update

Your site gets new projects every unit for the rest of the course. Here's the loop you'll use every time: edit and save in VS Code → upload to GitHub → commit.

  1. In VS Code, make one small change. For example, add <p>Last updated: October 2026</p> to your footer on all three pages. Save, and check Live Preview.
  2. On github.com, go to your repo's front page → Add file → Upload files.
  3. Drag in everything inside your your-slug folder.
  4. Write a commit message that says what changed (Add last-updated date to footer) → Commit changes.
  5. Wait about a minute, then reload your live site with Ctrl + F5 (a hard refresh).
Good commit messages say what changed: "Add dark mode toggle" or "Fix broken avatar link." Messages like "stuff," "asdf," or "final FINAL v2" don't count. Your commit history is part of your portfolio now, and people can read it.
Deleted or renamed a file? Uploading only adds and replaces files. It never removes anything, so the old file stays on GitHub as an extra. That's usually harmless. To tidy up, open the old file on GitHub, click the ⋯ menu (top right of the file) → Delete file → Commit changes.

This matters for capital letters: if you rename Avatar.PNG to avatar.png, GitHub keeps both, because to GitHub they're different files. Your site works, since your HTML points to the new one. Delete the old one to keep your repo clean.
🟢 Green: your change shows up on the live site, and your repo's commit list shows at least three commits with clear messages.
🔴 Red: the live site hasn't changed. Check that you saved in VS Code before uploading, wait another minute, and hard refresh with Ctrl + F5.
