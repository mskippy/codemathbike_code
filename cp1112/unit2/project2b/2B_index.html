2B — Structure It

Build it so it's organized, documented, and hard to break.

This Level Is for You If…

  • You're comfortable writing Python, and Unit 1 didn't stretch you much.
  • You've met classes and try/except (in Extended Unit 1 or somewhere else).
  • You want to use them in a real program, not just a practice exercise.

What You'll Build

A console program from the problem menu: a calculator-type tool, a quiz engine, or a simple tracker. This time it's designed around at least one class.

The class should model the main "thing" in your program, like a Quiz, a Tracker or a Converter. It shouldn't just be a wrapper around a function you already had.

How to do the debugger walkthrough

  1. Pick a bug you actually hit, or a spot where you weren't sure what your code was doing.
  2. Click just left of a line number to set a breakpoint (a red dot). Put it on the line before things go wrong.
  3. Press F5 and choose Python Debugger → Python File. Your program runs and pauses at the red dot.
  4. Look at the Variables panel on the left. Use Step Over (F10) to go one line at a time and watch the values change.
  5. Take a screenshot, and write down what the values were and what that told you.

The last sentence is the important part. "Here's a breakpoint" isn't a walkthrough. "score went back to 0 on every question, so I realized I was resetting it inside the loop" is.

When You're Stuck

  • Revisit the Extended Unit 1 notebooks on classes and try/except. They're in your 1_python_learning/practice folder.
  • Use the debugger, not print statements. Set a breakpoint on the line before things go wrong and watch the Variables panel.
  • If your class feels pointless, ask yourself: "What data does this thing hold, and what can it do?" If the answer is "nothing" and "one thing," it might not need to be a class yet.
  • Keep try/except small. Wrap the one line that can fail, not the whole program. Otherwise you'll hide real bugs.

Done Looks Like…

Your main program reads almost like plain English, because the class does the heavy lifting. Bad input gets a friendly message every time. Someone could read your docstrings and use your class without reading the code inside it.
