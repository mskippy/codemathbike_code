Unit 2 · Level 2D

2D — Engineer It

Build it the way professional developers do: designed, tested, and version-controlled properly.

This Level Is for You If…

  • You're confident in Python, and classes feel natural.
  • Your code usually works, and now you want it to be well-built.
  • You want to learn the habits that separate working code from well-engineered code.

What You'll Build

A program from the problem menu (calculator-type tool, quiz engine, or simple tracker) with a real object-oriented design: multiple classes that work together. It's backed by automated tests and built on a git branch.

Your project folder will look something like this:

2_quiz_engine/
├── README.md
├── main.py              ← your classes and main program
└── tests/
    └── test_quiz.py     ← your unittest tests

Your mentoring session

Sometime in Week 2, your teacher will pair you with a 2A student. Spend some time helping them get unstuck, then log it in the Mentoring Log section of your README.

Your job is to ask questions, not to type. Try "What do you expect this line to do?" and "What did it actually do?" If you take the keyboard, you've taken over.

Make your log specific. "Helped with loops" isn't enough. "Asked what range(5) produces, and they found the off-by-one themselves" is.

Setting up your dev branch (CP1)

  1. In GitHub Desktop, click Current Branch at the top, then New Branch.
  2. Name it dev and click Create Branch. Leave it based on main.
  3. Click Publish branch so it's on GitHub too.
  4. From now on, check that Current Branch says dev before you commit.

Writing and running your tests

Your test file goes in tests/ and its name has to start with test_. A tiny example:

import unittest
from main import Question

class TestQuestion(unittest.TestCase):
    def test_correct_answer_is_marked_right(self):
        q = Question("Capital of BC?", "Victoria")
        self.assertTrue(q.check("victoria"))

if __name__ == "__main__":
    unittest.main()

To run all your tests, open a terminal in your project folder (the one with main.py in it) and run:

python -m unittest discover -s tests -v
Tests running your whole program? When a test imports main.py, Python runs everything in it, including your menu loop. Put the line that starts your program inside if __name__ == "__main__": so it only runs when you run main.py directly.

Merging dev into main (CP3)

  1. Commit and push everything on dev first.
  2. Click Current Branch and switch to main.
  3. Click Current Branch again, then Choose a branch to merge into main. Pick dev, and click Create a merge commit.
  4. Click Push origin.

Got a merge conflict? Don't panic, and don't delete anything. Put a hand up and your teacher will walk through it with you.

When You're Stuck

  • The Python docs for unittest are your main reference.
  • If a class is getting big, it's probably two classes.
  • If tests are hard to write, your functions may be doing too much at once. Split them up. (A method that both asks for input and does the math is hard to test. Keep those separate.)
  • For branching, GitHub Desktop's Current Branch menu handles create, switch, and merge.

Done Looks Like…

Another developer could clone your repo, run your tests with one command, see them pass, and understand your design from the class sketch alone. Your commit history shows a real branch-and-merge workflow.
